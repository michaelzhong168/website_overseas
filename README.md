# website_overseas

海外品牌展示站（信息架构与体验层级可参考 [Minotti](https://www.minotti.com)，视觉与素材须自有版权，勿照搬竞品站点）。

---

## 开发与上线节奏

**先完成开发与测试，再部署阿里云正式环境。**

测试阶段在本地或独立测试环境完成验收；仅当版本通过「测试完成标准」后，再部署到生产账号下的阿里云资源（与测试环境隔离）。

---

## 阶段一：开发与测试（不上生产）

### 本地

- 前后台与数据库建议用 Docker Compose（PostgreSQL，按需加 Redis）跑通。
- 使用 `.env.example` 说明变量；生产专用变量（正式 OSS、正式域名等）在本地可留空或使用占位，勿将真实密钥提交仓库。

### 测试环境（可选）

- 可用低配云主机或独立资源组做联调/演示，须与**生产 VPC、生产 RDS、生产 OSS、生产域名**隔离，数据脱敏或使用假数据。

### 测试完成标准（验收勾选）

- [ ] 核心前台页面与导航可用（首页、系列/产品、案例或灵感、新闻、联系等，以实际范围为准）
- [ ] 后台可完成内容维护：创建/编辑/发布、媒体上传、多语言与 SEO 字段（若项目包含）
- [ ] 权限与鉴权：未授权无法访问管理接口与后台
- [ ] 表单/线索流程可端到端验证（入库或通知，按设计）
- [ ] CI 通过：lint、类型检查、约定范围内的自动化测试
- [ ] 主要用户路径手工回归无阻塞缺陷
- [ ] 冻结可上线候选：指定 **Git 标签或构建产物（镜像/制品）**，后续生产仅部署该版本

---

## 阶段二：阿里云正式部署（测试通过后）

仅在上述验收完成后执行。

- 生产资源独立：VPC、安全组、RDS PostgreSQL、OSS、CDN、域名与 HTTPS 证书、负载均衡（多实例时）。
- 数据库与中间件不暴露公网；密钥通过控制台或 KMS 注入，不进仓库。
- 配置备份、监控告警、日志采集；准备发布步骤与回滚方式（回退上一镜像或上一标签）。

---

## Agent 分工提示

- 用 OpenAPI/共享类型定义衔接前后台，减少串行等待。
- 每个任务明确：输入契约、产出物、依赖阶段、验收标准。
- 设计 Token（色板、间距、字阶）集中维护，保证前台风格一致。
